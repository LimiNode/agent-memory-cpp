# agent-memory-cpp

**Библиотека на C++17 для создания систем памяти и поиска информации в ИИ-агентах.**

[English](README.md) | [Русский](README-RU.md)

`agent-memory-cpp` помогает приложению сохранять документы, диалоги, события и знания, вести их историю, находить релевантную информацию и собирать проверяемый контекст для модели. Проект рассчитан на локальное и встраиваемое использование: ядру не нужны отдельный процесс Python или обязательный внешний сервис памяти.

Это библиотека и исследовательско-инженерный проект, а не LLM, готовый ассистент, облачная платформа памяти или среда управления агентом. Приложение само владеет моделями, решениями, инструментами, расписанием и правом выполнять действия.

## Зачем использовать библиотеку?

- **Встраивать в своё приложение.** Ядро — нативная библиотека C++17/CMake с необязательными адаптерами хранения и моделей.
- **Хранить содержимое с историей.** Канонические документы имеют стабильные идентификаторы блоков, неизменяемые ревизии, чтение прошлых состояний и детерминированную материализацию.
- **Разделять хранение, поиск и доказательность.** Предметные контракты не требуют одной конкретной БД, а частота извлечения не становится доказательством достоверности.
- **Собирать разные профили памяти.** Целевая модель объединяет историю диалогов, документы, события, знания, отношения и процедурный опыт с нужными приложению маршрутами поиска.
- **Измерять поведение.** Эталонные результаты, воспроизводимые отчёты и подтверждающие данные, эксперименты с кодеками и тесты ошибочных режимов важнее неподтверждённых обещаний качества.

## Что библиотека должна позволять строить

Ниже описана целевая модель возможностей. Это направление и набор контрактов проекта, а не утверждение, что всё перечисленное уже реализовано.

- Историю диалогов и память, производную от текущей сессии.
- Семантические, эпизодические, процедурные, временные профили памяти, а также память пользователя и проекта.
- Markdown и структурированные документы, события, факты, сущности и отношения.
- Точный, лексический, плотный векторный, гибридный, графовый и временной поиск, переранжирование и сборку контекста.
- Подключаемые адаптеры эмбеддингов и моделей, реализации индексов и backend'ы хранения.
- Локальные базы знаний и приложения агентов, которым нужна память без обязательного внешнего сервиса.

Текущий статус перечислен ниже и в [аудите покрытия](guides/retrieval-roadmap-coverage.md).

## Чем проект отличается

- Это встраиваемая предметная библиотека, а не готовая платформа агента со своим runtime, инструментами и моделью.
- Каноническое содержимое, история ревизий и происхождение данных являются частью дизайна, а не непрозрачным blob за векторным индексом.
- Backend'ы реализуют предметные контракты, например хранилища канонического содержимого; библиотека не навязывает всем БД универсальный интерфейс `IDatabase`.
- Поиск и статус доказательств разделены. Кандидат может быть возвращён или попасть в контекст, не становясь текущим, проверенным или разрешённым к использованию в действии.
- Репозиторий явно публикует статусы реализации и критерии исследовательских этапов. Сбалансированные отличия от близких проектов приведены в [сравнении проектов](guides/project-comparison.md).

## Архитектура

Целевой поток данных:

~~~mermaid
flowchart TD
    S["Документы / диалоги / события"] --> C["Нормализация и сохранение канонических представлений"]
    C --> P["Ревизии, происхождение и жизненный цикл"]
    P --> I["Лексические / векторные / графовые / временные проекции"]
    I --> R["Поиск и сборка ContextPack"]
    R --> A["Приложение / модель агента"]
    B["Память в процессе / MDBX / будущие backend'ы"] -.-> C
~~~

Адаптеры хранения, реализации индексов и провайдеры моделей выбираются на уровне композиции поверх предметных контрактов. Схема показывает направление архитектуры, а не готовность каждого блока.

## Что реализовано сейчас

| Область | Уже доступно | Пока нет законченного пользовательского пути |
|---|---|---|
| Нативная основа | Библиотека C++17/CMake, предметные интерфейсы и типы, тесты и примеры | Готовое приложение памяти агента |
| Канонический текст | Эталонное чтение, редактирование и материализация в памяти, стабильные блоки, ревизии и net change set | Полное редактирование многодоменных и мультимодальных данных |
| Постоянное каноническое содержимое | Необязательный **MDBX C1** для raw/plain: общий контекст, история ревизий, привязка тела и журнал запрета повторного использования ID | Сжатие и перекодирование C2, полноценная публикация между хранилищами и восстановление |
| Поиск и индексы | Ограниченные примитивы точного, лексического и векторного поиска, контракты и исследовательские стенды | Полноценная реализация гибридного, графового и временного поиска, включая BM25F, и автоматическая сборка контекста |
| Доказательства и жизненный цикл | Контракты, фикстуры и протоколы исследований | Сквозное применение происхождения, временной семантики, feedback и полномочий |
| Несколько контекстов | Независимые MDBX-контексты и задокументированные границы размещения и федерации | Готовый маршрутизатор рабочих пространств, федеративный исполнитель, разнородные backend'ы и межконтекстная публикация |

[Аудит покрытия](guides/retrieval-roadmap-coverage.md) является источником статусов. Метки `Implemented`, `Contract only`, `Docs/tests only` и `Roadmap only` означают разное. Межконтекстная ACID-гарантия не входит в дизайн: у независимых контекстов разные границы транзакций и снимков.

## Основные компоненты

- **Каноническое содержимое:** `ICanonicalContentStore`, `ICanonicalContentEditor` и `InMemoryCanonicalContentStore` задают эталонный контракт чтения, редактирования и истории. `MdbxCanonicalContentStore` — необязательный адаптер постоянного хранения C1.
- **Предметная модель:** типизированные идентификаторы, метаданные, ревизии канонических документов, стабильные блоки и net change set.
- **Поиск и индексы:** точные лексические и векторные примитивы, интерфейсы retriever'ов, адаптеры оценки и экспериментальные реализации индексов.
- **Точки интеграции:** эмбеддинги, ingestion, хранение и адаптеры моделей/runtime подключаются отдельно от канонического предметного контракта.
- **Оценка:** таблицы покрытия, точные оракулы, протоколы исследований и воспроизводимые receipts фиксируют, что реализовано, описано контрактом или ещё исследуется.

## Сборка и быстрый старт

Требования: **C++17**, **CMake 3.20+** и поддерживаемый компилятор для Windows, Linux или macOS.

~~~bash
git clone --recursive https://github.com/LimiNode/agent-memory-cpp.git
cd agent-memory-cpp

cmake -S . -B build -DCMAKE_BUILD_TYPE=Release \
  -DAGENT_MEMORY_BUILD_TESTS=ON \
  -DAGENT_MEMORY_BUILD_EXAMPLES=ON

cmake --build build --config Release
ctest --test-dir build --build-config Release --output-on-failure
~~~

Поддержка MDBX **выключена по умолчанию**. Для адаптера C1 включите `-DAGENT_MEMORY_ENABLE_MDBX=ON` и подготовьте заявленные зависимости `libmdbx` / `mdbx-containers`. Основная цель — `agent_memory::agent_memory`, общий заголовок — `<agent_memory.hpp>`.

### Минимальный пример канонического содержимого

Полный исполняемый пример — единственный источник истины для этого сценария: [`examples/canonical_content.cpp`](examples/canonical_content.cpp). Он создаёт ревизию `0`, публикует одно изменение, материализует историческую и текущую Markdown-версии и проверяет, что содержимое ревизий не смешивается.

Основная форма публичного API:

~~~cpp
InMemoryCanonicalContentStore store;
const auto result = store.commit(
    CanonicalEditRequest{document_id, 0, std::move(operations)}
);
const auto previous = store.materialize_markdown(document_id, 0);
const auto current = store.materialize_markdown(document_id);
~~~

Собрать и запустить полный пример:

~~~bash
cmake -S . -B build \
  -DAGENT_MEMORY_BUILD_TESTS=ON \
  -DAGENT_MEMORY_BUILD_EXAMPLES=ON
cmake --build build --config Release
ctest --test-dir build --build-config Release \
  -R "^agent_memory_canonical_content_example$" --output-on-failure
~~~

Полный набор семантических сценариев описан в [контракте канонического содержимого](guides/canonical-content-storage-roadmap.md), [публичном заголовке](src/agent_memory/storage/CanonicalContentStore.hpp) и [тестах канонического содержимого](tests/domain/canonical_content_test.cpp).
