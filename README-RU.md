# agent-memory-cpp

**Встраиваемая основа на C++17 для памяти и поиска в ИИ-агентах.**

[English](README.md) | [Русский](README-RU.md)

Память агента — это не просто поиск по векторам. Долго работающему агенту нужно сохранять исходные данные, учитывать изменения, различать наблюдения и выводы, извлекать значимый прошлый опыт и собирать контекст, не превращая часто повторяемые утверждения в «доказанные факты».

`agent-memory-cpp` — **библиотека и исследовательско-инженерный проект**, а не готовый ассистент, LLM, облачная служба памяти или система управления агентом. Модели, решения, инструменты, планирование и полномочия на действия остаются у приложения.

**Подробное [сравнение с другими проектами](guides/project-comparison.md)** объясняет отличия от Mem0, Letta, Graphiti/Zep, Cognee, A-MEM, графового RAG и библиотек векторного поиска. Расширенный каталог источников — в [related projects](guides/related-projects.md).

## Зачем он нужен

- **Встраивание вместо обязательного сервера.** Ядро — статическая библиотека C++17; для её работы не требуются Python или отдельный сервер векторной БД.
- **Редактируемая память с историей.** Стабильные идентификаторы блоков, неизменяемые ревизии документов, чтение истории, независимые логические версии тела и физические поколения хранения.
- **Разделение памяти и достоверности.** Происхождение данных, производные утверждения, время действия, влияние памяти и ошибки обратной связи описаны нормативными контрактами и исследованиями. Не всё из этого уже реализовано.
- **Независимость предметного API от БД.** Эталонное хранилище в памяти процесса и необязательный MDBX-адаптер реализуют один предметный интерфейс. Другие БД пока остаются направлением развития.
- **Измеримые решения.** Эталонный точный поиск, эксперименты с кодеками и маршрутизацией, воспроизводимые результаты и тесты на ошибочные режимы важнее обещаний «самой быстрой памяти».

### Место в приложении

~~~text
Приложение / среда агента (модели, инструменты, решения, права)
                           |
       политики памяти / планирование контекста     [в основном планы]
                           |
       предметные контракты поиска и содержимого
              /                            \
    эталонные реализации             адаптеры хранения
    в памяти процесса                 MDBX C1 raw/plain
                           |
       независимые тесты и исследовательские стенды
~~~

В целевую систему входят типизированные единицы памяти, лексический, векторный, графовый и временной поиск, сборка контекста и жизненный цикл памяти. **Схема показывает архитектуру, а не список готовых промышленных функций.**

|---|---|---|
| Основа | Библиотека C++17/CMake, предметные интерфейсы и типы, тесты и примеры | Готовое приложение долговременной памяти |
| Канонический текст | Эталонное хранилище с чтением, редактированием, материализацией, ревизиями и стабильными блоками | Полная работа с диалогами и мультимодальными данными |
| Постоянное хранение | Необязательный **MDBX C1**: raw/plain содержимое, общий контекст, история ревизий, привязка тела, запрет повторного использования ID | C2-сжатие, полная межхранилищная публикация и восстановление |
| Поиск | Небольшие реализации точного, лексического и векторного поиска, контракты и экспериментальные стенды | Полный промышленный BM25F + dense + graph + temporal стек и автоматический планировщик контекста |
| Доказательства и жизненный цикл | Контракты, наборы проверок и исследовательские протоколы | Сквозное применение происхождения, временных правил, feedback и полномочий |
| Несколько баз данных | Возможность создавать независимые MDBX-контексты; документированные границы маршрутизации и федерации | Готовый маршрутизатор workspaces, разнородные backend'ы и межконтекстные ACID-транзакции |

## Принципы архитектуры

1. **Логическая идентичность не зависит от файла БД.** Ревизии документа, блока и тела не определяются алгоритмом сжатия или путём MDBX. Размещение по нескольким контекстам пока описано контрактом, а не готовым маршрутизатором.
2. **Частота извлечения не доказывает достоверность.** Кандидат, выданный результат, выбор в контекст, разрешение передачи провайдеру и фактическое использование — разные этапы.
3. **Один контекст БД — одна граница транзакций.** Несколько MDBX-файлов или сочетание MDBX с SQLite/CAS не дают общей ACID-транзакции.
4. **Модели подключаются отдельно.** Генерация эмбеддингов, LLM, извлечение сущностей и автономное поведение принадлежат адаптерам либо внешней среде агента.

## Сборка

Требования: **C++17**, **CMake 3.20+**, компилятор под Windows, Linux или macOS.

~~~bash
git clone --recursive https://github.com/LimiNode/agent-memory-cpp.git
cd agent-memory-cpp

cmake -S . -B build -DCMAKE_BUILD_TYPE=Release \
  -DAGENT_MEMORY_BUILD_TESTS=ON \
  -DAGENT_MEMORY_BUILD_EXAMPLES=ON

cmake --build build --config Release
ctest --test-dir build --build-config Release --output-on-failure
~~~

Поддержка MDBX **по умолчанию отключена**. Для адаптера C1 используйте отдельную конфигурацию с `-DAGENT_MEMORY_ENABLE_MDBX=ON` и подготовьте зависимости `libmdbx` / `mdbx-containers` (подмодули, предоставленные родительским проектом цели или установленные библиотеки).

Цель CMake — `agent_memory::agent_memory`, общий заголовок — `<agent_memory.hpp>`. Для необязательных MDBX-адаптеров предусмотрены отдельные заголовки. См. [примеры](examples/) и [параметры сборки](cmake/AgentMemoryOptions.cmake).
