# Calibration-work optimizer for static radius-one MIH

## 2026-08-12 — pre-execution contract

### Question

Does a direct calibration-only optimizer return a static radius-one MIH layout
with less candidate work than the current 32 x 8 ITQ-256 partition, when it
may select both widths and bit assignment?

### Contract

The optimizer reads only the frozen 25,000-vector calibration train split. It
does not accept an evaluation root and therefore cannot read held-out query
vectors, qrels, E5-oracle outcomes, or retrieval metrics. A stable hash-selected
128-vector subset of calibration train IDs acts as pseudoqueries; the full
25,000-vector train split is the indexed corpus.

For each ITQ seed 52--56, it directly measures local-radius-one work and uses
this lexicographic objective:

1. mean unique candidate union;
2. mean posting visits;
3. p95 posting visits;
4. lower width variance, lexicographic widths, then permutation as deterministic
   ties.

Widths are generated by a bounded transfer search from 32 x 8, retaining total
code length 256 and 32 bands. The fixed bound is widths 6--10 and at most two
one-bit transfers; it is an algorithmic search space, not a hand-written list
of shapes. For every generated profile, two deterministic assignment restarts
perform twelve cross-band bit-swap proposals, accepting a proposal only when
the directly measured objective improves. Thus both the width profile and bit
assignment are selected on measured calibration work rather than the earlier
collision-information surrogate.

The held-out follow-up matrix, if this optimizer finds a non-control layout,
will compare its returned layout with equal 32 x 8 and a width-matched random
assignment. If it returns 32 x 8, that is itself the useful result: within this
predeclared bounded direct-work search, equal width is the selected static
radius-one partition. It does not establish an exhaustive theorem over every
possible static partition, query-adaptive probing, or MIH-aware code learning.

### Expected result

The balanced-bit null model and the previous 6/7/9/10 negative result suggest
that 32 x 8 may remain selected. The direct objective is still necessary: it
tests actual union overlap and postings on the calibration corpus rather than
assuming independent bits or optimizing collision information indirectly.
